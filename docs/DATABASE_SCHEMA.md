# DDC Agriculture CRM — Database Schema Specification

> **Engine**: PostgreSQL 15+ (Supabase) | **Migrations**: `supabase/schemas/` + `supabase/migrations/*_ddc_*.sql`
> **Verification**: All DDL, constraints, triggers, functions, RLS policies, and grants are continuously verified against PGlite via `npm run test:db`.

---

## 1. Global Schema Standards

1. **Primary Keys**: `bigint generated by default as identity` for transactional entities; constrained snake_case `text` keys (`^[a-z][a-z0-9_]*$`) for system lookup catalogs (`ddc_roles`, `permission_resources`, `option_categories`).
2. **Timestamps**: All timestamps stored in UTC (`timestamp with time zone`). UI formats schedules and displays in `Asia/Bangkok` (UTC+7). `updated_at` maintained by `ddc_touch_updated_at()` trigger.
3. **Soft Deletion**: High-value master & commercial tables carry `deleted_at timestamp with time zone` (nullable, indexed with partial `WHERE deleted_at IS NULL` where appropriate) to prevent irreversible data loss. Hard deletion is restricted to administrators or explicitly non-destructive child rows.
4. **Optimistic Concurrency Control**: Core mutable entities include `version integer not null default 1`, automatically incremented on UPDATE by `ddc_bump_version()`. API writes validate `If-Match` / `expected_version` and reject stale updates with HTTP `409 Conflict`.
5. **Security-by-Default (RLS)**: Every table in `public` MUST have `ENABLE ROW LEVEL SECURITY` and explicit least-privilege policies. `anon` has ZERO read/write access to business or configuration tables (only `SELECT` on `public.init_state`).
6. **Append-Only Audit Trail**: `public.audit_log` records DML via `ddc_audit()` trigger, redacting sensitive credential keys and truncating inline base64 photo payloads (`>2048` chars). Optional correlation headers (`app.request_id`, `app.actor_ip`, `app.actor_user_agent`, `app.audit_reason`) are recorded per transaction.
7. **Expand-and-Contract Migrations**: Never drop/rename active columns or destroy production data in a single step. Add nullable/defaulted structures first, migrate code, and only contract after verification and explicit approval.

### 2.5 Admin Control Plane Tables *(Phase 1)*
| Table | Purpose | Key Invariants |
|---|---|---|
| `ui_config_versions` | Versioned typed UI config (`Draft → Validated → Approved → Scheduled → Published → Superseded/Rolled Back`) | Partial unique index `ui_config_versions_one_published_per_env` guarantees atomic single active config per environment |
| `feature_flags` & `feature_flag_history` | Runtime flags with user/role/team targeting, deterministic rollout %, schedules, kill switch, immutable history | `rollout_percentage BETWEEN 0 AND 100`; kill switch overrides `is_enabled` |
| `releases` & `deployments` | Immutable release artifacts (`development`/`staging`/`production`) and deployment history with approval, health checks, smoke tests, and rollback links | Production deployments require `releases.approval_status = 'approved'` |
| `scheduled_jobs` & `scheduled_job_logs` | Durable background jobs (`pending`/`scheduled`/`running`/`completed`/`failed`/`cancelled`/`retrying`) with `idempotency_key` and `locked_by`/`locked_until` leases | Unique partial index on active `idempotency_key` prevents duplicate job execution |
| `api_idempotency_keys` | Stores response snapshots for idempotent write endpoints (`Idempotency-Key` header) | Scoped per `(actor_user_id, endpoint, idempotency_key)` with TTL `expires_at` |
| `backup_records` | Backup catalog, checksums, verification timestamps, retention dates | `backup_management` / admin only |

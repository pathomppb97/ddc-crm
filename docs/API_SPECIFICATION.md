# DDC Agriculture CRM — API-First Specification

> **OpenAPI 3.1 Contract**: [docs/openapi/v1.openapi.yaml](./openapi/v1.openapi.yaml)
> **Shared Contracts & Query Builder**: `packages/shared-api/`
> **Gateway Runtime**: `apps/api/` + `supabase/functions/api_v1/`

---

## 1. Versioning & Namespace Separation

All enterprise endpoints are strictly versioned under `/v1` and separated into two security domains:

| Namespace | Audience | Purpose |
|---|---|---|
| `/api/v1/*` | CRM Web Application, Mobile Field Sales, Authorized Service Accounts | Business CRM operations: customers, contacts, machines, parts, compatibility, leads, opportunities, visits, RFQs, quotations, sales orders, price lists, targets, forecasts, search, aggregations, saved views, bulk/import/export |
| `/admin/v1/*` | Independent Admin Control Center, Release Automation | Control plane operations: system overview, users, sessions, roles/permissions, field permissions, teams, data scopes, query builder, API keys, UI config versions, feature flags, releases, deployments, scheduled jobs, audit logs, backups, integrations, settings |

## 2. Standard Request & Response Envelopes

### Headers
- `Authorization: Bearer <jwt>` OR `X-Api-Key: <ddc_key>` (for authorized service accounts on permitted endpoints)
- `X-Request-Id: <uuid>` (propagated or generated by server; echoed in every response and recorded in `audit_log.request_id`)
- `Idempotency-Key: <unique-key>` (required/supported on create, bulk, workflow transitions, publish, deploy, and job enqueue endpoints)
- `If-Match: "<version>"` (optional/recommended optimistic concurrency guard on `PATCH`/`PUT`)

### Success Envelope
```json
{
  "data": {},
  "meta": {
    "page": 1,
    "pageSize": 25,
    "total": 142,
    "totalPages": 6,
    "sort": [{ "field": "updated_at", "direction": "desc" }],
    "timezone": "Asia/Bangkok"
  },
  "requestId": "req_01J..."
}
```

### Error Envelope (RFC 9457-aligned)
```json
{
  "error": {
    "code": "FORBIDDEN",
    "message": "Permission denied for customers:delete",
    "details": {},
    "requestId": "req_01J..."
  }
}
```

| HTTP Status | Error Codes |
|---|---|
| `400` | `VALIDATION_ERROR`, `INVALID_QUERY`, `INVALID_FILTER_FIELD`, `INVALID_OPERATOR` |
| `401` | `UNAUTHENTICATED`, `TOKEN_EXPIRED`, `ACCOUNT_DISABLED`, `MFA_REQUIRED` |
| `403` | `FORBIDDEN`, `SCOPE_DENIED`, `ADMIN_REQUIRED` |
| `404` | `NOT_FOUND` |
| `409` | `CONFLICT`, `VERSION_MISMATCH`, `IDEMPOTENCY_CONFLICT`, `WORKFLOW_VIOLATION` |
| `422` | `UNPROCESSABLE_ENTITY`, `BUSINESS_RULE_VIOLATION` |
| `429` | `RATE_LIMITED` (includes `Retry-After`, `X-RateLimit-Limit`, `X-RateLimit-Remaining`) |
| `500` | `INTERNAL_ERROR` (never leaks stack traces, SQL internals, or secrets) |

## 3. Core Endpoint Catalog

### 3.1 Business API (`/api/v1`)
| Method & Path | Description | Permission |
|---|---|---|
| `GET /api/v1/health` | Liveness & build metadata (no secrets) | Public / authenticated |
| `GET /api/v1/me` | Current user identity, active role, effective permissions, data scope, active UI config & evaluated feature flags | Authenticated active user |
| `GET /api/v1/resources/{resource}` | Paginated list with sort, allowlisted filter, soft-delete exclusion (`deleted_at IS NULL`) | `{resource}:read` |
| `POST /api/v1/resources/{resource}` | Create record (supports `Idempotency-Key`) | `{resource}:create` |
| `GET /api/v1/resources/{resource}/{id}` | Fetch single record with field-level permission masking | `{resource}:read` |
| `PATCH /api/v1/resources/{resource}/{id}` | Partial update with optimistic concurrency (`version` / `If-Match`) | `{resource}:update` |
| `DELETE /api/v1/resources/{resource}/{id}` | Soft delete (`deleted_at = now()`) where supported | `{resource}:delete` |
| `POST /api/v1/query` | Controlled Dynamic Query Builder (allowlisted resource, fields, operators, groupBy, aggregations) | `{resource}:read` |
| `GET /api/v1/search?q=...` | Cross-entity global search enforcing RLS | Authenticated active user |
| `GET /api/v1/aggregations/dashboard` | Server-side aggregated KPIs (replaces 15 client full-table fetches) | `reports:read` |
| `GET/POST/PATCH/DELETE /api/v1/saved-views` | User and shared saved queries & table views | `reports:read` / owner |
| `POST /api/v1/bulk/{resource}` | Controlled bulk update / tag / soft-delete (async job when `>100` rows) | `{resource}:update` / `delete` |
| `POST /api/v1/imports/{resource}` | Enqueue Excel/CSV validation & import job | `{resource}:import` |
| `POST /api/v1/exports/{resource}` | Enqueue Excel/CSV export job (with field masking applied) | `{resource}:export` |
| `POST /api/v1/leads/{id}/convert` | Transactional lead conversion (idempotent) | `leads:update` |
| `POST /api/v1/quotations/{id}/submit\|approve\|reject\|status\|revise` | Quotation approval workflow state machine | `quotations:update` / `approve` |

## 4. Controlled Dynamic Query Builder Contract

Raw SQL is **strictly prohibited**. Every query request MUST conform to the Zod schema in `packages/shared-api/src/queryBuilder.ts`:

- **Allowlisted Resources**: Explicit catalog (`companies`, `contacts`, `leads`, `deals`, `products`, `machine_models`, `customer_machines`, `quotations`, `rfqs`, `sales_orders`, `activities`, `service_cases`, `audit_log`, etc.).
- **Allowlisted Columns & Types**: Per-resource typed column registry; sensitive columns (hashes, internal tokens) are excluded completely.
- **Allowlisted Operators**: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `in`, `contains`, `starts_with`, `is_null`, `between`. Operator compatibility is checked against column data type (e.g., `contains` only on `string`).
- **Safety Ceilings**:
  - Max filter conditions: `25`
  - Max nesting depth: `3`
  - Max `IN` list length: `100`
  - Max `pageSize`: `100` (default `25`)
  - Max `selectedFields`: `40`
  - Statement timeout: `10,000 ms`
- **Compilation**: Emits strictly parameterized clauses (`$1, $2, ...`) or PostgREST-safe query arguments; identifiers come exclusively from the static allowlist map, never user strings.

## 5. Rate Limiting & Idempotency

| Tier | Limit | Scope |
|---|---|---|
| Authentication / Password Reset | 10 req / min | Per IP + account |
| Standard CRM Business API (`/api/v1/*`) | 120 req / min | Per authenticated user / API key |
| Dynamic Query & Search (`/api/v1/query`, `/search`) | 60 req / min | Per user |
| Admin Write & Destructive Ops (`/admin/v1/*`) | 30 req / min | Per admin user |
| Bulk / Import / Export Enqueue | 10 req / min | Per user |

Write endpoints marked idempotent check `api_idempotency_keys` by `(actor_user_id, endpoint, idempotency_key)`:
- Same key + same SHA-256 request hash → replay stored status & response body.
- Same key + different request hash → `409 IDEMPOTENCY_CONFLICT`.
